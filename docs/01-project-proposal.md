# Document 1 — Project Proposal

## 1. 项目定义

**名称：** MolmoAct2-SO101：语言驱动桌面操作机器人的仿真、部署与鲁棒性评估。

**应用场景：** 家庭/实验室桌面内，用户以自然语言指定物体和目标区域，单臂机器人依据两路 RGB 视觉与自身关节状态执行操作。

**核心问题：** 将开源 VLA 模型从 checkpoint 可靠地接入低成本机械臂，处理观测格式、动作语义、相机标定、闭环延迟、安全限制和可重复评估。

**输入：**
- 自然语言指令；
- 第三视角 RGB 图像；
- 腕部 RGB 图像；
- SO-101 关节/夹爪状态；
- 运行配置和安全边界。

**输出：**
- 分块关节动作；
- 执行状态与安全事件；
- 每回合日志、视频、指标和失败标签。

## 2. 范围

### MVP（必须完成）

1. 固化 Windows/Ubuntu 或原生 Ubuntu 上的可复现推理环境。
2. 用官方 checkpoint 建立离线推理 baseline。
3. 采购、装配并标定一台 SO-101。
4. 接入第三视角与腕部相机。
5. 建立 observation → policy → safety gate → robot 闭环。
6. 完成三类演示：
   - 单物体抓取并放入指定容器；
   - 多物体中按语言选择目标；
   - 改变目标初始位置后的抓放。
7. 每类至少 20 个正式回合，保存完整证据。
8. 提供一键式启动说明、实验报告和 Demo 视频。

### Enhanced（完成 MVP 后）

- ROS 2 Jazzy 节点化、诊断与 rosbag2；
- 自动失败检测、有限次数重试；
- 背景、光照、遮挡和语言改写鲁棒性矩阵；
- 规则式/人工遥操作 baseline；
- 简单 Web 或 RViz 监控界面。

### Advanced（非 MVP）

- 采集 100–300 条 LeRobot 轨迹；
- 冻结 VLM、训练 action expert，或 LoRA 适配；
- 未见物体泛化与微调前后对照；
- MolmoAct2-Think 的深度推理可视化。

不包含：移动底盘、双臂、力控、危险/尖锐物体、高速运动、完整模型预训练、无人看护运行。

## 3. 最终 Demo

固定相机拍摄完整工作区；用户给出一条未硬编码的语言指令；系统显示两路图像、指令、推理延迟和安全状态；机器人抓取正确目标并放入指定容器；最后展示批量实验统计与典型失败，而不只展示剪辑后的成功案例。

## 4. 客观成功标准

| 项目 | 通过标准 |
|---|---|
| 环境 | 新建环境按锁定文件完成安装，自动 smoke test 通过 |
| 推理 | 连续 20 次请求无崩溃，记录 P50/P95 延迟和峰值显存 |
| 安全 | 超限动作被阻断；急停、通信超时和相机丢失测试全部通过 |
| 真机功能 | 3 类任务各完成 ≥20 个预注册回合；报告实际成功率，不设置虚构门槛 |
| 可复现 | 第二次全新启动按文档完成核心 Demo，不依赖未记录手工操作 |
| 工程质量 | 单测、集成测试、配置校验、日志和版本清单齐全 |
| 展示 | 原始结果、汇总表、失败样例和 Demo 视频可追溯 |

项目完成不要求达到论文成功率；要求测量过程可信、系统闭环完整、失败可解释。

## 5. 可行性结论

官方提供 SO-100/101 微调 checkpoint、LeRobot 工作流和真实部署参考。RTX 50 系列受官方 CUDA 12.8 环境覆盖，BF16 是首选；但 RTX 5080 的实际显存占用、吞吐和 SO-101 开箱表现必须由 TASK-004/005 验证。完整微调不进入 MVP，本地只承诺推理与小规模训练 smoke test。

## 6. 假设与决策

- ¥8,000 为总硬件/云资源上限，不包含现有电脑。
- 每天两小时按每周 7 天估算；计划仍预留休息和 2 周缓冲。
- 首选 Linux 原生或 WSL2 GPU 推理；USB 实机控制如在 WSL2 不稳定，切换为 Ubuntu 双系统/独立 Linux 控制端。
- MVP 购买一台 SO-101；第二台 leader arm 仅在 Advanced 且预算复核后考虑。
